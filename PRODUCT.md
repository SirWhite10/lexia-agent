# Product Router

Agent is a self-extensible agent: a permanent Rust host, WebAssembly Components for every capability, and provider-independent model access ([ADR 0005](docs/adr/0005-rust-agent-host-and-wasm-plugins.md)). Its interface is one gpui-kit codebase compiled to a native binary and a browser bundle ([ADR 0004](docs/adr/0004-rust-client-all-platforms.md)). SvelteKit is a slim host: auth, static serving, and the browser-native artifact renderers.

**Retiring.** The previous architecture — Jev routing into an EVE TypeScript runtime run by `eve dev` from `my-agent/` — is superseded and is removed by [WF-IMP-025](docs/planning/tickets/WF-IMP-025-retire-eve-and-the-typescript-agent.md). It still runs today and is still described below; treat every mention of EVE, `my-agent/` and `eve dev` as pending deletion, not as current architecture. Build nothing new on it.

Two surfaces describe that routing rather than performing it. `/thinking` is the **thought tree**: an editable graph of the questions Agent asks itself, drawn blueprint-style and edited in a side panel. A new workspace opens on the pipeline the host actually runs — capture, retrieve, assemble, run, reflect — and **Restore default pipeline** adds back only the nodes a tree is missing, so the operator's own edits survive. It is the map, not the runtime: Jev, the routing decision, has no code behind it yet and the page says so. `/settings/models` maps **use-cases** (Always, Quick answers, Research and search, Heavy work, plus any the operator adds) to provider models, which the host consults; EVE's own model still comes from its authored `my-agent/agent/agent.ts`.

- `my-agent/agent/` — **retiring.** EVE agent source: instructions, model config, channels, tools, skills, subagents. Removed by [WF-IMP-025](docs/planning/tickets/WF-IMP-025-retire-eve-and-the-typescript-agent.md); its content is superseded by the agent host's prompt and skills, not ported.
- `agents/default/` — **the agent data directory.** The default agent's manifest, instructions, memory, skills, sub-agents, plugin pointers and provider configuration, as data the host watches ([ADR 0005](docs/adr/0005-rust-agent-host-and-wasm-plugins.md)). Nothing in it is compiled and nothing in it needs a rebuild to change. The contract — structure, and which paths are watched — is [agents/default/README.md](agents/default/README.md). `subagents/` holds one directory per standing sub-agent.
- `templates/agent/` — the template every agent directory is created from, committed as a readable tree; `templates/agent.zip` is the same tree packed so creating an agent needs no template checkout. Used by [WF-IMP-026](docs/planning/tickets/WF-IMP-026-agent-directory-loader-and-watch.md)'s loader and by `scripts/agent.ts`.
- `src/` — SvelteKit application and server integration. Planned; clients contain access/UI concerns only.
- `src/lib/components/ui/` — shadcn-svelte primitives. Planned.
- `src/lib/components/kit/` — GPUI Kit browser port: component layer plus the crate's default theme, scoped to `.kit`. Web is alpha per [WF-DEC-003](docs/planning/tickets/WF-DEC-003-gpui-kit-forefront-web-alpha.md); this is the reference implementation and parity oracle for the GPUI Kit migration, not a shipping surface. Its README records the crate source for every value.
- The whole route set converts to it, not chat and artifacts alone, and SvelteKit keeps the address bar authoritative. Order: [WF-IMP-012](docs/planning/tickets/WF-IMP-012-url-and-session-bridge.md) (URL and session bridge) → [WF-IMP-013](docs/planning/tickets/WF-IMP-013-port-app-shell-to-gpui-kit.md) (shell) → surfaces, with [WF-IMP-018](docs/planning/tickets/WF-IMP-018-host-dom-island-bridge.md) alongside for the artifact kinds the host still renders best.
- `src/routes/kit/` — UI test page: the chat interface, the live component set and the artifact gallery, at phone, tablet and desktop widths.
- `src/lib/components/ai/` — Svelte-native AI interaction components. Planned.
- `src/lib/components/features/` — Agent feature compositions. Planned.
- `gpui-app/` — the Rust crate: the **agent host** and, later, the gpui-kit client. One source tree producing a native binary and a `wasm32` bundle per [ADR 0004](docs/adr/0004-rust-client-all-platforms.md); the host's architecture is [ADR 0005](docs/adr/0005-rust-agent-host-and-wasm-plugins.md). Today it holds the binary, its HTTP surface and the provider-independent model layer ([WF-IMP-019](docs/planning/tickets/WF-IMP-019-rust-agent-binary-and-model-layer.md)); the loop, coordinator, plugin host and client arrive in later tickets. The desktop shell is a plain Rust binary linking `gpui-pre-platform` — a webview shell cannot host a GPUI canvas, so **Tauri is not used anywhere in this project** and there is no `src-tauri/`. See [gpui-app/README.md](gpui-app/README.md).
- `app-data/state/` — **migrating.** Persistent Agent and workflow state: SQLite run/action records and the event log, thought-tree and use-case rows, attachment metadata, plus agent memory and personality files. Uploaded bytes live beside it in `app-data/state/attachments/`. Moves to the agent host's state directory per [ADR 0005](docs/adr/0005-rust-agent-host-and-wasm-plugins.md), one writer at every point in the cutover.
- `docs/planning/agent-runtime-v0.1.md` — what v0.1 contains, what replaces what, and the order of work across the agent and client chains.
- `docs/planning/agent-capabilities-v1.md` — current planning baseline for intent plans, durable execution, and initial integrations; distinguishes selected scope from open provider validation.
- `docs/planning/tickets/` — Wayfinder-style investigation, decision, prototype, and implementation tickets for planned agent capabilities.
- `DESIGN.md` — current normative design-system baseline; once `spec.mdx`, `spec-config.ts`, and `spec:gen` exist, update it through those sources instead of editing it directly.
